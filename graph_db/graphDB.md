# 뉴스 수집·그래프 DB

최종 수정: 2026-11-17 17:15 (KST)

뉴스 수집과 그래프 DB를 **어떤 순서로, 어떤 규칙으로 만드는지** 정리한 문서다. 본문에는 확정된 내용만 적고, 아직 정하지 않은 것은 맨 끝 [결정할 것](#결정할-것)에 모은다. 처음 보는 사람은 루트의 [`graph_news_overview.md`](../graph_news_overview.md)(짧은 안내)부터 읽는다.

**읽는 법**: 1장에서 전체 흐름을 보고, 궁금한 단계의 장으로 간다.

| 장 | 다루는 단계 | 한 줄 요약 |
|---|---|---|
| 1 | 전체 흐름 | 노트북이 어떤 순서로 무엇을 읽고 만드는지(1.1), 그래프를 어떻게 갱신하는지(1.2) |
| 2 | 대상 | 그래프와 검색어를 만들 종목 951개(코스피 전체 + 코스닥150), 업종 26개, 테마 125개 |
| 3 | DART 공시 | 공시를 받아 지분·계열 표를 읽고, 사업보고서에서 제품·고객·경쟁사를 LLM으로 뽑는다 |
| 4 | 미국 뉴스 | 언론사 RSS로 상시 수집하고, 뉴스가 아닌 글을 거른다 |
| 5 | LLM 추출 | DART·뉴스에서 개체·관계·사건을 뽑는 공통 규칙, 지시문, 비용 |
| 6 | 그래프 구축 | 기업 이름 통일 → 제품 사전 → Neo4j 그래프 → 검색어 |
| 7 | 실험 기록 | 규칙을 정할 때 한 실험과 결과 |

## 1. 목적과 전체 흐름

서비스는 한국 아침에 **밤사이 미국에서 나온 뉴스 중 사용자 보유 종목과 관련된 것**을 보여 준다. 그래프 DB는 두 가지에 쓴다.

1. **검색어 만들기**: 밤사이 미국 뉴스를 구글 뉴스 RSS로 찾을 영어 검색어를 만든다. 검색어는 `graph_db`의 별도 노트북(`search_terms`, 6.5)이 그래프를 다시 만들 때마다 **서비스 대상 후보 전체**에 대해 미리 만들어 종목코드 기준 표로 내보낸다. 검색과 그 뒤 처리(거르기, 같은 소식 묶기, 본문 받기)는 프로젝트 루트의 `news_search/`가 그 표에서 **보유 종목의 검색어만** 골라 한다(결정은 [`news_search/news_search.md`](../news_search/news_search.md)).
2. **연결 경로 보여주기**: 뉴스가 어떤 경로로 보유 종목과 이어지는지 보여 준다(예: SK하이닉스 → 주요 고객 Nvidia → Nvidia 실적 뉴스).

밤사이 뉴스는 **세 유형**으로 본다. **시장 전체**(거시 지표, 정치, 지정학), **산업**(보유 종목의 업종·테마), **종목 직접**(보유 종목과 그래프로 이어진 기업·제품). 산업과 종목 직접은 그래프로 판별하고, 시장 전체는 매일 밤 프롬프트가 알아본다([`nightly_prompt_requirements.md`](../nightly_prompt_requirements.md)).

연결은 성격에 따라 다른 자료에서 가져온다.

| 연결 | 예 | 자료 |
|---|---|---|
| 지분·계열 | LG에너지솔루션 → Ultium Cells(GM 합작사) | DART 지분 표. 법으로 실명 공개라 정확하다. 미국 뉴스는 한국 모회사보다 현지 법인 이름으로 나온다 |
| 제품·고객·경쟁 | 삼성전자 → HBM, 한미반도체 → 고객 Micron | DART 사업보고서 "사업의 내용"(LLM 추출) |
| 공급망·사건 | Doosan Enerbility → NuScale 원자로 부품 수주 | 미국 뉴스(LLM 추출). 공시에서 익명("A사")인 상대가 뉴스에는 실명으로 나온다 |
| 업종·테마 | 미국 반도체 업황 → 반도체 업종 종목, 방산 테마 종목 | WI26 업종, 토스증권 테마 |

국내 기업과 해외 기업은 직접 관계가 없어도 **제품 노드를 거쳐** 이어진다(SK하이닉스 → HBM ← Micron·Nvidia).

### 1.1 처음 구축: 데이터가 지나가는 노트북

모두 `graph_db/` 노트북이고, 결과는 `graph_db/source/` 아래에 쌓인다. 앞 단계의 결과 파일만 읽으므로 어느 단계든 다시 돌릴 수 있다. LLM 단계는 원본 응답을 보관하고, 같은 지시문·입력이면 다시 보내지 않는다(입력 해시).

```
DART 공시  dart_targets → dart_collector → dart_parser ─────────────────────────────────── 지분·계열 표
                                         └ dart_business_parser → dart_business_extractor(LLM) → dart_business_cleaner ─ 제품·고객·경쟁
미국 뉴스  news_collector(윈도우 PC 상시) → news_filter → news_extractor(LLM) → news_cleaner ─ 개체·관계·사건
                                    ↓
           name_unifier(기업 이름 통일) → product_dictionary(제품 사전, 규칙) → product_llm(제품 사전, LLM) → product_apply(LLM 사전 적용)
                                    ↓
           graph_db(Neo4j) → search_terms(검색어) → 구글 뉴스 RSS 검색(news_search/, 보유 종목의 검색어만)
```

| 단계 | 노트북 | 읽는 것 | 만드는 것(`source/` 아래) |
|---|---|---|---|
| 대상 | `dart_targets` | `market_data/sector.json`, 지수 구성 종목, KRX 일별매매 | `targets.csv`(서비스 대상 후보 951개) |
| DART 받기 | `dart_collector` | `targets.csv` | `dart/raw/`(API 응답·원문 zip), `dart/selected_reports.csv` |
| 지분·계열 | `dart_parser` | `dart/raw/` | `dart/parsed/`(기업, 종속회사, 관계기업, 출자, 최대주주, 수시공시, 계열회사) |
| 사업의 내용 | `dart_business_parser` → `dart_business_extractor`(LLM) → `dart_business_cleaner` | 사업보고서 원문 | `dart/business/inputs/`(LLM 입력) → `extract/raw/`(LLM 원본) → `final/dart_business_v5.json`(최종본) |
| 뉴스 받기 | `news_collector`(윈도우 PC) | 언론사 RSS·기사 페이지 | 공유 MySQL(`news`) → 맥에는 스냅샷 `news/snapshot_*/news.sqlite3` |
| 뉴스 거르기 | `news_filter` | 공유 DB 또는 스냅샷 | `news/filter/article_filter.csv`(기사마다 본문/요약/제외) |
| 뉴스 추출 | `news_extractor`(LLM) → `news_cleaner` | 거른 기사 | `news/extract/raw/`(LLM 원본) → `news/final/news_final.json`(최종본) |
| 기업 이름 통일 | `name_unifier` | DART 최종본·지분 표(법인 주주·계열회사 현황 포함), 뉴스 최종본, `sector.json`, DART 고유번호 목록 | `graph/companies.csv`, `company_mentions.csv`(언급 → 기업 ID), `country_names.csv`(영어 → 한글 나라 이름) |
| 제품 사전(규칙) | `product_dictionary` | DART·뉴스 최종본 | `graph/products.csv`, `brands.csv`, `product_mentions.csv`(언급 → 노드) |
| 제품 사전(LLM) | `product_llm`(제품군 목록 → 1단계 노드 분류 → 2단계 계층) | 규칙 사전 | `products/llm/`(제품군 확정본, 1단계 그룹, 2단계 원본, 그리고 원래 언급 → 제품·계층·후보로 정리한 표) |
| LLM 사전 적용 | `product_apply` | 규칙 사전의 언급·브랜드, `product_llm`이 내보낸 표(`products/llm/llm_*.csv`, 3단계 `stage3_brands_*.csv`) | `graph/products_final.csv`(제품군·제품·후보·임시 노드), `product_mentions_final.csv`(언급 → 제품), `product_hierarchy.csv`(계층), `brands_final.csv`(브랜드 + 종류), `brand_products.csv`(브랜드 → 제품). LLM 결과가 없는 새 언급은 규칙 노드로 이어 둔다 |
| 그래프 | `graph_db` | 이름 통일 표, `product_apply`의 제품·브랜드 표, DART·뉴스 최종본, `targets.csv`, `sector.json`, `toss_theme.json` | `graph/neo4j/`(노드·관계 CSV), `graph/sources/`(기사·공시 출처 목록), Neo4j |
| 검색어 | `search_terms`(6.5) | `graph_db`가 만든 노드·관계 표(`graph/neo4j/`), `targets.csv` | 서비스 대상 후보 951개 **모두**의 검색어를 미리 만든 표(종목코드 기준). 구글 뉴스 RSS 검색은 이 표에서 보유 종목의 검색어만 골라 쓴다 |
| 뉴스 검색 | `news_search/news_collect.ipynb`(24시간 수집), `news_search/news_process.ipynb`(수집 마감 뒤 처리), `news_search_tests/search_tests.ipynb`(검색 방식 시험) | `search_terms`의 검색어 표, `news_source_tests`의 구글 뉴스 언론사 판정 | 매체 제한(`site:`, OR 묶음) 구글 뉴스 RSS 응답 원본과 기사 목록, 묶음·본문·프롬프트 입력(`news_search/source/`). 결정은 `news_search/news_search.md` |

### 1.2 갱신: 그래프에 새 정보를 넣는 흐름

**갱신할 때마다 그래프 전체를 새로 만든다.** 새 자료(밤사이 뉴스, 새 공시)를 쌓인 자료에 더한 뒤 공통 단계를 처음부터 다시 돌리고, Neo4j를 비우고 통째로 넣는다. 새 관계만 골라 기존 그래프에 더하는 방식(`MERGE`)은 쓰지 않는다. 규칙 단계(이름 통일, 제품 사전)와 적재가 몇 분이면 끝나 언제든 전체를 다시 만들 수 있고, 그래프가 항상 지금 규칙·사전과 맞아 단순하기 때문이다. 비용이 드는 LLM 단계는 입력 해시로 새로 들어온 것만 보낸다(이미 처리한 기사·회사·제품은 건너뛴다).

| 흐름 | 주기 | 지나가는 노트북 | 정한 것 / 정할 것 |
|---|---|---|---|
| **DART** | 월 1회 | `dart_collector`(지난 한 달 새 정기공시·주요사항보고가 있는 대상 기업만) → `dart_parser` → `dart_business_parser` → `dart_business_extractor`(입력이 바뀐 회사만 LLM) → `dart_business_cleaner` → 공통 단계 | 정함(3.1) |
| **미국 뉴스** | 미정(매일은 아님) | 수집과 밤사이 프롬프트는 매일(`news_search` 검색 + `news_collector` 상시 수집 → 프롬프트의 그래프용 추출을 쌓아 둠). 그래프 반영은 쌓인 추출을 모아 일정 주기로 한 번씩: `news_cleaner` → 공통 단계 | 프롬프트는 팀원 작업과 합침(#15, `nightly_prompt_requirements.md`). 그래프 반영 주기(#27) |
| **새 제품** | 미정 | 공통 단계의 `product_dictionary`가 이름 키로 기존 노드에 맞춘다. 맞는 노드가 없는 새 제품만 `product_llm` 1단계로 분류하고, 새 제품이 쌓인 제품군만 2단계를 다시 한다 | 주기와 방식(#26) |
| **공통 단계** | 위 흐름마다 | `name_unifier` → `product_dictionary` → `product_llm`(새 제품만) → `product_apply` → `graph_db` → 검색어 | 정함: 매번 전체를 새로 만든다 |
| **기준 자료** | 6월·12월 등 | 지수 구성 종목이 바뀌면 `dart_targets` → `dart_collector`(새 종목만). `sector.json`·`toss_theme.json`은 다시 받으면 `graph_db`부터 | 대상 변경(#4), 테마 파일(#23) |

- 그래프를 다시 만들면 노드 ID가 바뀔 수 있다(상장 폐지, 대표 이름 변경). 그래프 밖(보유 종목, 검색어 결과)에는 종목코드로 저장한다(6.4).
- LLM 결과는 노드 번호·줄 번호가 아니라 **원래 언급(출처, 문서, 자리, 이름)**에 붙여 둔다. 규칙을 고쳐 노드가 바뀌어도 결과가 다른 노드에 잘못 붙지 않게 하기 위해서다.

## 2. 대상 기업, 업종, 테마

**서비스 대상 후보: 951개 = 코스피 전체 + 코스닥150** (`dart_targets.ipynb` → `source/targets.csv`, 2026-11-17 정함). 서비스할 수 있는 종목의 최대 범위다. 이 목록에 없는 종목은 서비스 대상이 되지 않는다. 실제 서비스 대상(코스피200 + 신뢰할 만한 코스닥 기업 일부, 야간선물 기반 시가 예측 파트와 같은 대상)은 이 안에서 고른다. 공시 수집·관계 추출, 그래프의 상장사 노드와 업종·테마 연결은 모두 이 목록을 기준으로 한다.

`market_data/sector.json`의 상장사 2,655개에서 아래 묶음을 순서대로 고른다(한도에 걸려 수집이 멈춰도 앞 묶음부터 받아 두려는 순서).

| 묶음 | 기준 | 수 |
|---|---|---|
| 코스피200 | 구성 종목 | 201 |
| 코스피 | 나머지 코스피 | 600 |
| 코스닥150 | 구성 종목 | 150 |

- 빼는 종목: 우선주, 리츠·인프라펀드(이름이 "리츠"·"인프라"로 끝남), 해외 기업(종목코드 9로 시작), 코스닥의 스팩·관리종목·투자주의환기종목. 코스닥150 구성 종목 중에는 여기에 걸리는 것이 없다.
- 코스닥은 코스닥150만 쓴다. 그 전에 코스닥150 밖에서 소속부·시가총액 상위 300·거래대금 10억원 이상으로 고른 116개(코스닥 추가)는 2026-11-17 대상에서 뺐다. 이 116개는 공시를 이미 받아 관계를 뽑아 두었으므로, 그래프에는 **서비스 대상이 아닌 상장사 노드**로 남는다(`target` 거짓, 업종·테마 연결 없음, 사업보고서·지분 표에서 뽑은 관계는 그대로). 공시 수집·파싱(`dart_collector`, `dart_parser`, 사업의 내용 추출)은 다시 돌리지 않는다.
- 코스피200·코스닥150이 바뀌면(6월·12월) 구성 종목 파일을 새로 받아 `dart_targets` → `dart_collector`를 다시 돌린다. 이미 받은 기업은 건너뛴다.

**업종: WI26 26개** (`market_data/sector.json`). 서비스 대상 후보에 업종을 붙여, 관계가 뚜렷하지 않은 기업도 업종 뉴스로 잇는다. 뉴스 추출 결과의 `sectors`도 WI26 이름을 쓴다.

**테마: 토스증권 상위 태그 125개** (`market_data/toss_theme.json`, 2026-11-12 받음)

- 업종은 사용자에게 직관적이지 않을 때가 있어(방산 종목 58개가 WI26에서는 8개 업종에 흩어짐) 익숙한 테마를 함께 쓴다.
- 토스 원본 세부 분류(285개)는 쓰지 않는다. 제품 수준의 연결은 제품 사전이 맡는다.
- 파일에 종목코드가 없어 `sector.json`의 종목 이름으로 코드를 찾는다. 서비스 대상 후보 중 테마가 빈 종목은 1개(SHD)로, 업종만 쓴다.
- WI26과 이름이 같은 테마(반도체, 자동차 등 13개)도 그래프에서는 업종 노드와 따로 둔다.

`sector.json`·`toss_theme.json`은 2,655개 그대로 둔다. 다른 파트와 같이 쓰는 자료이고, 지수 구성 종목이 바뀌면 `targets.csv`를 다시 고르는 재료이기 때문이다. 후보만 쓰는 것은 그래프 노트북이 `targets.csv`로 거른다.

## 3. DART 공시

국내 기업이 **누구와 지분으로 엮였는지**(표, 규칙으로 읽음)와 **무엇을 만들고 누구와 거래하는지**(사업보고서 본문, LLM으로 뽑음)를 얻는다.

### 3.1 받기 (`dart_collector.ipynb`)

- **OpenDART API**로 받는다(무료, 하루 약 2만 건). 대상을 951개로 줄이기 전의 1,067개(코스닥 추가 116개 포함)를 받았고, 약 1.8만 건이었다.
- **기업마다 가장 최근 보고서**를 쓴다. 최근 2년 공시 목록에서 직접 고르고, 고른 보고서는 `source/dart/selected_reports.csv`에 남긴다.
  - 타법인 출자: 사업·반기보고서 중 최신 / 최대주주: 사업·반기·분기보고서 중 최신 / 종속회사·관계기업·사업의 내용: 최신 사업보고서 원문
  - 원문은 정정 전 보고서까지 찾아 **본문이 들어 있는 가장 최근 보고서**를 받는다(`[첨부정정]`은 본문이 없다).
- **갱신은 월 1회**: 지난 한 달 동안 올라온 정기공시·주요사항보고 중 대상 기업 것만 골라 그 기업만 다시 받는다. 정기보고서는 1년에 두 번만 바뀌어 실시간일 필요가 없다.
- **상대가 실명인 자료만 쓴다.** 익명("A사", "북미 전기차 업체")은 쓰지 않는다.
- 모든 관계에 근거 공시의 접수번호(`rcept_no`)를 남긴다.

### 3.2 지분·계열 표 (`dart_parser.ipynb` → `source/dart/parsed/`)

| 표 | 자료 | 줄 수 | 그래프에서 |
|---|---|---|---|
| `companies.csv` | 기업개황 | 1,067(대상을 951개로 줄이기 전에 받은 것) | 영문 정식명칭, 시장, 업종 |
| `subsidiaries.csv` | 사업보고서 XII. 종속회사 | 19,236 | 해외 법인(주소·나라) |
| `associates.csv` | 재무제표 주석 관계기업·공동기업 | 8,357 | 합작사(지분율·나라) |
| `investments.csv` | 타법인 출자현황 | 19,936 | 출자(목적·지분율) |
| `shareholders.csv` | 최대주주 현황 | 9,101 | 해외 모회사(법인 주주만) |
| `decisions.csv` | 양수·양도, 합병·분할 결정 | 175 | 보고서 사이의 지분 변화 |
| `affiliates.csv`, `affiliate_groups.csv` | 사업보고서 IX. 계열회사(요약표의 기업집단 이름, 상세표의 계열회사 목록) | 53,980 | 그룹 소속 |

- 정리 단계에서는 거르지 않는다. 출자 목적은 `purpose_group`(경영참여/단순투자/일반투자/기타)으로 묶어 두고, 거르기는 그래프에서 한다.
- 말이 안 되는 값(지분율 0~100% 밖 등)은 빈칸으로 둔다. 이름의 각주 표시는 지우고 영문 약칭(`(SEA)`)은 `alias`로 뗀다.
- 관계기업 주석은 서식이 회사마다 달라 주석 제목과 열 제목으로 표를 찾는다.
- 계열회사 목록의 상장 회사는 법인등록번호 → 이름에 적힌 종목코드 → 이름(한글로 풀어 쓴 영문 약칭 "엘지"·"씨제이"는 영문으로 바꿔) 순서로 종목코드를 찾는다(3,637줄 중 3,396줄. 못 찾은 것은 대부분 리츠·합병으로 없어진 회사·해외 법인).

### 3.3 사업의 내용 (`dart_business_parser` → `dart_business_extractor` → `dart_business_cleaner`)

**입력 만들기** (`dart_business_parser`, 비용 없음): 사업보고서 "II. 사업의 내용"에서 필요한 부분만 잘라 회사별 입력 파일(`inputs/종목코드.txt`, 중앙값 약 8,100자)을 만든다.

| 부분 | 얻는 것 |
|---|---|
| 2. 주요 제품 및 서비스, 3. 원재료 및 생산설비 | 제품, 매출 비중, 원재료, 실명 매입처, 생산 거점 |
| 4. 매출 및 수주상황 중 판매경로·수주 | 판매 채널, 실명 고객, 수주 |
| 6. 주요계약 (연구개발은 건강관리 업종만) | 기술이전·라이선스·공급계약 상대 |
| 1·7절 중 "시장점유율"·"경쟁" 단락 | 실명 경쟁사, 점유율 |

- 금융 서식(은행·보험·증권)은 "1. 사업의 개요"만 쓴다. 생산능력·가동률, 판매 조직, 숫자뿐인 표는 뺀다.
- 표(매출 부문·원재료·사업장)는 규칙으로도 읽어 `tables/`에 둔다. 매출 숫자는 이 표를 쓴다.

**LLM 추출** (`dart_business_extractor`): 제품(본문에만 있는 세부 제품 포함)·영어 이름·검색어·용도, 브랜드, 원재료와 실명 매입처, 실명 고객·경쟁사, 시장점유율, 계약, 가격 변동 항목을 뽑는다(5장).

**최종본** (`dart_business_cleaner` → `final/dart_business_v5.json`): 회사별 결과를 하나로 합치며 규칙으로 고친다. 고친 것은 모두 `changes.csv`에 남는다.

| 번호 | 고치는 것 | 처리 |
|---|---|---|
| ① | 근거가 원문과 다름 | 원문에서 가장 비슷한 부분(일치율 0.85 이상)으로 바꾸고, 없으면 그 항목을 뺀다 |
| ② | 자기 자신이 상대 | 뺀다 |
| ③ | 지분 관계만 적은 기타 관계("○○의 자회사") | 뺀다(지분은 3.2 표를 쓴다). 사업 내용이 있으면 남긴다 |
| ④ | 국내 사업장 단위 상대(재건축 조합, PFV, 리츠) | 이름으로 유형이 분명한 것만 뺀다 |
| ⑤ | 표의 글자 띄움("전 장"), 같은 항목 중복 | 붙이고, 하나만 남긴다 |

결과: 1,063개 회사, 항목 약 3.8만 개(제품 13,739, 브랜드 5,015, 원재료 5,253(실명 매입처 4,046), 고객 2,979, 경쟁사 1,688, 계약 3,526). 정리로 뺀 것은 약 400개(기타 관계 198, 고객 124, 매입처 61, 계약 58 등). 모든 근거가 원문에 있다.

## 4. 미국 뉴스

공시에서 익명인 거래 상대의 실명과 해외 기업·제품 소식을 얻으려고 미국 언론사 기사를 상시로 모은다. 여기 기사는 **그래프 재료**이고, 매일 아침 보여 줄 기사를 찾는 구글 뉴스 검색은 `news_search/`가 따로 한다.

### 4.1 수집 원칙

- **기사 목록은 언론사 공식 RSS로만** 받는다(사이트맵 금지). **본문은 RSS에 있으면 쓰고, 없으면 기사 페이지에서 추출**한다.
- robots.txt를 지키고(RFC 9309, 가장 긴 규칙 우선), 로그인·유료벽·봇 차단은 우회하지 않는다. 봇 보호에 막힌 기사는 다시 요청하지 않고 RSS 제목·요약만 쓴다.
- 기사 문장을 그대로 쓰지 않고, 정해 둔 사실 정보만 LLM으로 뽑아 그래프를 만든다.
- 과거 기사를 찾아 받지 않는다. 수집을 시작한 뒤 RSS에 올라온 기사만 쌓는다.

### 4.2 수집기 (`news_collector.ipynb`, 윈도우 PC 상시 실행)

- 일반 경제 매체는 1분마다, 업종 전문지는 15분마다 받는다(서버가 더 긴 캐시 시간을 주면 따른다).
- 기사 ID는 정규화한 주소의 해시다. 새 기사만 저장하고, 내용이 바뀐 기사는 이전 내용을 따로 남긴다.
- 같은 서버는 2초 간격, 기사 페이지는 60초 간격(같은 회사 서버는 묶어서). 429·503은 기다렸다 다시, 401·403은 24시간 뒤 다시 확인한다.
- 오류·차단·중단은 텔레그램으로 바로 알리고, 매일 오전 9시에 24시간 요약을 보낸다.
- 기사는 **윈도우 PC의 MySQL**(공유 DB)에 쌓는다. 같은 네트워크의 팀원이 읽기 전용 계정으로 접속한다. 설정이 없으면 SQLite에 쌓는다.

| 루머·유출 기사가 섞임 | Tom's Hardware |
| 소비자 리뷰·사용법 위주 | Motor1, Engadget |
| 업계 관계 뉴스가 적음 | Chemical Processing |
| 사용자 결정 | Hydrocarbon Processing |

### 4.4 본문 정제와 거르기

**본문 정제** (수집기가 수집할 때)

- 기사 페이지에서는 본문 영역만 뽑고, 광고·구독 안내·사진 출처·기자 소개 같은 줄은 지운다(지운 줄은 규칙 이름과 함께 남긴다).
- 후원 기사(주소 `/sponsored/`, 첫 줄 "Sponsored by…")와 영상 페이지는 쓰지 않는다.
- 본문을 제대로 읽었는지 상태를 남긴다: `ok`, `short`, `suspect`, `paywalled`, `sponsored`, `blocked`, `empty` 등.

**뉴스가 아닌 글 거르기** (`news_filter.ipynb`): 수집할 때는 다 저장하고, 여기서 주소·분류 태그·제목으로 표시한다(지우지 않는다).

| 거르는 것 | 예 |
|---|---|
| 후원·광고, 영상·팟캐스트·사진, 시세·라이브 페이지 | Sponsored 태그, `/video/`, `live-updates` |
| 생활·커리어, 외부 기고, 매체 홍보·행사 안내, 인사 동정 모음 | CNBC `/make-it/`, Opinion 태그, 웨비나 안내 |
| 영어가 아닌 기사, 오래된 기사(처음 수집 때 이미 90일 지남), 같은 제목 중복 | |

- 주간 모음 기사는 남긴다. 정치·사건 기사는 규칙으로 거르지 않고 LLM이 "관련 없음"으로 판단한다.

**추출에 쓰는 입력**

| 본문 상태 | 입력 |
|---|---|
| `ok`, `short`, `suspect` | 제목·매체·발행 시각 + 본문 |
| `blocked`, `paywalled`, `empty` 등 | 제목·매체·발행 시각 + RSS 요약 |
| `sponsored`, `skipped_rule` 등 | 쓰지 않는다 |

- 그래프는 스냅샷 `snapshot_20261112_1127`(2,725건)로 만들었다. 거르고 남은 **2,471건**(본문 2,357, 요약 114)을 쓴다.

## 5. LLM 정보 추출 (DART·뉴스 공통)

문서(회사 하나의 사업의 내용, 기사 하나)를 LLM에 보내 **개체·관계·사건을 정해진 JSON 형식으로** 받는다. 받은 원본은 고치지 않고 보관하고, 규칙으로 정리한 최종본을 그래프에 쓴다.

### 5.1 실행 수단과 비용

| 작업 | 수단 | 모델 |
|---|---|---|
| 지시문 다듬기(시범 문서로 여러 번) | Codex 구독(비용 없음). 결과 분석은 Claude Code | `gpt-6.1-terra` |
| 그래프 첫 구축의 전체 추출 | OpenAI 배치 API(일반 요청의 50% 가격, 24시간 안 처리) | `gpt-6.1-terra` |
| 매일 밤 새 뉴스 | OpenAI API 일반 요청(결과를 바로 받아야 해 배치를 쓰지 않음) | `gpt-6.1-terra` |

- 실제 비용: DART 1,063개 중 배치 966개 $12.60(긴 회사 97개는 Codex), 뉴스 2,471건 $14.37(기사당 약 $0.0058).
- 매일 밤 처리는 일반 요청이라 요청당 약 $0.012다(`news_v5` 추출 기준, 요약·종목 판단을 더하면 는다). 요청은 기사가 아니라 묶음마다라, 2026-11-16 첫 실전(시험 종목 18개, 옛 1차·2차 방식)은 묶음 86개(하룻밤 약 $1)였고, 수집 마감 한 번 방식 시험(11-16 밤)은 63개였다. 보유 종목이 늘면 묶음 수가 는다.

### 5.2 공통 원칙

- **문서 하나 = 요청 하나.** DART는 회사 하나, 뉴스는 기사 하나다.
- **개체 종류(8)**: 기업, 제품·기술, 상품·브랜드, 원자재·지표, 프로젝트·계약, 시설, 정책·규제, 기관
- **관계 역할(15 + 기타)**: 공급, 구매·사용, 생산, 수주·발주, 인수·투자, 매각, 합작·제휴, 라이선스, 경쟁, 규제·인허가, 시설 건설·운영, 영향(+/−), 소송·분쟁, 자금 지원, 정책 입장, 기타. "기타"는 어디에도 맞지 않을 때만 쓰고 짧은 설명을 붙인다.
- **이름**: 원문 표기, 영어 표준 이름, 미국 기사가 쓰는 영어 검색어, 한 단계 위 범주를 남긴다. 너무 일반적인 말("AI", "oil")은 검색어로 쓰지 않는다.
- **근거**: 항목마다 원문 문장을 그대로 남기고 번호로 가리킨다. 근거가 원문에 그대로 있는지 기계로 확인한다.
- **추론하지 않는다**: 문장이 두 대상의 관계를 직접 말할 때만 뽑는다. 단순 나열·스치는 언급은 개체로만 남기고, 제품 이름으로 회사를 추정하지 않는다. 익명 상대는 빼고, 증권사 투자의견이나 상대 없는 계획은 관계로 뽑지 않는다.
- **언어**: 이름·검색어는 영어, 사람이 읽는 설명은 우리말, 근거는 원문 그대로.

### 5.3 지시문과 결과 형식

| | DART | 뉴스 |
|---|---|---|
| 지시문 | `prompts/dart_business_v5.md` | `prompts/news_v5.md` |
| 결과 형식(JSON 스키마) | `prompts/dart_business_v5.schema.json` | `prompts/news_v5.schema.json` |
| 입력 | 회사 하나의 사업의 내용 발췌 | 기사 하나(제목·매체·시각 + 본문 또는 요약) |

- 지시문 짜임: 역할과 목적 → 입력 설명 → 판단 원칙 → 항목별 기준과 예 → 결과 형식.
- API는 지시문을 `instructions`, 입력을 `input`으로 보내고 JSON 스키마(엄격 모드)로 형식을 강제한다. 형식 오류는 0건이다.
- 매일 밤 뉴스 처리 LLM은 적재용 요약과 그래프용 추출을 함께 하는 별도 프롬프트를 쓰고, 추출 부분은 `news_v5`를 거의 그대로 포함한다.
- 지시문은 최종 버전 하나만 둔다(제품 사전·검색어 지시문도 같다: `product_node_v4`, `product_tree_v4`, `product_brand_v3`, `search_base_v4`, `search_company_v2`). 지시문을 바꾸면 버전을 올리고 결과를 섞지 않는다. 버전마다 무엇을 왜 고쳤는지는 7장 실험 기록과 각 노트북의 버전 표에 남긴다.

**DART 결과** (회사 하나)

| 칸 | 내용 |
|---|---|
| `evidence` | 근거 목록(e1, e2…: 원문 문장·표 한 줄) |
| `products`, `brands` | 제품(영어 이름, 범주, 사업부문, 검색어, 용도, 판매 중/개발 중), 브랜드(자사/고객사) |
| `materials` | 원재료와 실명 매입처 |
| `customers`, `competitors` | 실명 고객(주요 고객/판매 채널/수주 상대), 실명 경쟁사 |
| `market_shares`, `contracts`, `price_items`, `other_relations` | 점유율, 계약(기술이전·라이선스·공급·합작), 가격 변동, 기타 관계 |

**뉴스 결과** (기사 하나)

| 칸 | 내용 |
|---|---|
| `relevant`, `article_type`, `sectors`, `topics` | 관련 기사인지, 기사 종류(9), 관련 WI26 업종(최대 3), 주제 |
| `evidence` | 근거 목록(s1, s2…: 기사 문장 그대로) |
| `entities` | 개체: 기사 표기, 영어 이름, 종류, 범주, 검색어, 나라·모회사·티커(기사에 적힌 것만), 언급 정도(중심/실질/스침) |
| `relations` | 주체 → 역할 → 대상, 매개 제품, 금액·기간, 상태(체결/검토/진행/완료/차질/철회/유예), 확실성(회사 발표/보도/소식통/소문), 근거 번호 |
| `events` | 사건: 종류(실적, 가격·지표 변동, 정책, 공급 차질, 사고, 소송·조사, 경영진 교체, 거래·계약, 제품·사업 변화), 우리말 한 줄 설명, 관련 개체, 방향(+/−), 근거 1~3개 |

예(뉴스, 줄임):

```json
{"relevant": true, "article_type": "계약·수주", "sectors": ["기계", "유틸리티"],
 "evidence": [{"id": "s1", "text": "Under the contract, Doosan Enerbility will manufacture the upper reactor coolant system …"}],
 "entities": [{"id": "n1", "name_en": "Doosan Enerbility Co., Ltd.", "type": "기업", "country": "South Korea", "mention": "중심"},
              {"id": "n2", "name_en": "NuScale Power Corporation", "type": "기업", "mention": "중심"}],
 "relations": [{"subject": "n1", "role": "수주·발주", "object": "n2", "status": "진행", "certainty": "회사 발표", "evidence_id": "s1"}]}
```

### 5.4 원본 보관과 실행 기록

```
문서 원문 → LLM 원본 결과(보관, 고치지 않음) → 최종본(규칙으로 정리) → 이름 통일 → 제품 사전 → 그래프(언제든 다시 만듦)
```

- 응답은 받은 그대로 문서별 파일로 `raw/`에 남긴다. 실행마다 `runs.csv`에 한 줄(문서, 입력 해시, 지시문 버전, 실행 수단, 모델, 상태, 토큰, 비용)을 쓴다.
- 다시 뽑을 문서는 실행 기록으로 고른다(다른 지시문 버전, 입력이 바뀐 문서, 실패한 문서). 가공 단계를 고쳐도 다시 뽑지 않는다.
- 원본은 사람이 고치지 않는다. 고칠 것은 수정 파일에 적어 정리 단계에서 적용한다.
- 바탕화면이 iCloud 동기화 폴더라, 파일을 지웠다 다시 쓰면 "이름 2" 사본이 생긴다. 생성 파일은 내용이 바뀐 것만 쓰고, 읽을 때는 정해진 이름 형식만 읽는다.

### 5.5 뉴스 추출과 최종본

**추출** (`news_extractor.ipynb`): 실행 수단(`RUNNER`)은 `codex`(지시문 시험) 또는 `batch`(전체 추출)다. 배치는 제출 → 다시 실행하면 결과를 받아 기사별로 나누고, 남은 기사는 다음 배치로 보낸다(`news_loop.py`가 10분마다 자동으로 하고 텔레그램으로 알린다). 같은 실행 수단으로 성공한 기사는 다시 보내지 않는다.

**최종본** (`news_cleaner.ipynb` → `source/news/final/news_final.json`): v5 결과만 쓴다(같은 기사에 여럿이면 배치 결과). 고친 것은 `changes.csv`에 남는다.

| 번호 | 고치는 것 | 처리 |
|---|---|---|
| ① | 근거가 원문과 다름 | 가장 비슷한 원문으로 바꾸고, 없으면 그 근거를 쓰는 항목을 뺀다 |
| ② | 관계가 아닌 것 | 자기 자신이 상대, 증권사 투자의견, 없는 개체·없는 근거 번호를 가리키는 관계를 뺀다 |
| ③ | 겹치는 관계 | 같은 주체·역할·대상·제품은 하나만. 공급과 같은 거래인 구매·사용은 뺀다 |
| ④ | 너무 일반적인 검색어 | 검색어에서만 뺀다 |

**결과**: 2,471건(관련 없음 82건), 개체 19,029, 관계 7,900, 사건 4,262.

- 관계는 생산 29%, 인수·투자 11%, 합작·제휴 10%, 시설 건설·운영 9%, 규제·인허가 9%, 구매·사용 7%, 공급 6% 순이고 기타는 3%다.
- 근거 대조 검토에서 주체·대상·방향이 틀린 관계는 찾지 못했다. 상태가 가끔 어긋나고(생산 중단 예정 기사가 "진행"), 게임 제목·패션 컬렉션처럼 덜 중요한 관계가 많아 그래프에서 점수로 낮춘다.
- 관련 기사 중 524건은 관계 없이 사건만 있다(시장·가격, 거시 기사). 그래프에 더하는 관계는 없고, 이런 기사는 매일 밤 서비스에서 기사 분류(`nightly_prompt_requirements.md`)로 다룬다.

## 6. 그래프 구축

DART·뉴스 최종본의 이름들을 같은 대상끼리 묶고(기업 이름 통일 6.2, 제품 사전 6.3), 노드·관계 표를 만들어 Neo4j에 넣은 뒤(6.4), 그 그래프에서 종목마다 검색어를 만든다(6.5).

### 6.1 엔진과 적재

- 그래프 DB는 **Neo4j**다. 노트북이 노드 표와 관계 표(CSV, `source/graph/neo4j/`)를 먼저 만들고, Neo4j를 비운 뒤 통째로 넣는다. 표는 원본에서 언제든 다시 만들 수 있다.
- 노드마다 **고정 ID**를 둔다. 같은 대상이 여러 번 나와도 노드 하나다.
- 규칙이나 사전이 바뀌거나 새 자료가 들어오면 표를 다시 만들어 통째로 다시 넣는다. 뉴스 반영도 매일 하지 않고 일정 주기로 한 번씩 같은 방식으로 한다(1.2, 주기는 #27).
- 개발용 Neo4j는 맥의 Docker 컨테이너 `neo4j-graph`(5.26 Community)다. 데이터는 Docker 볼륨에 두고(iCloud 폴더 밖), 이 맥에서만 접속한다(브라우저 http://localhost:7474, 프로그램 `bolt://localhost:7687`, 접속 정보는 `.env`의 `NEO4J_*`). 켜기·끄기는 `docker start/stop neo4j-graph`.

### 6.2 기업 이름 통일 (`name_unifier.ipynb`)

DART와 뉴스에 나온 기업 언급을 기업 노드 하나로 묶는다.

- ID: 상장사 `KR:종목코드`, 그 밖에는 정규화한 영어 이름 `EN:`, 영어 이름이 없으면 한글 이름 `KO:`.
- 같은 회사로 잇는 근거: ① 정규화한 이름이 같음(법인 표기·문장부호·악센트 무시) ② 한 언급의 한글·영어 이름 ③ 약칭·검색어가 전체에서 한 회사만 가리킴. 5자 이하 약칭(ADI, AV)은 ③으로만 잇는다.
- 상장사 이름: DART 기업개황을 받은 1,067개(서비스 대상 951개 + 대상에서 뺀 코스닥 116개)는 DART 기업개황의 종목명·법인명·영문 법인명으로 잇는다. 후보 밖 상장사 1,588개도 `KR:종목코드`로 잇되(같은 회사가 한글로는 `KR:`, 영어로는 `EN:`으로 갈리지 않게), 이름이 같은 다른 회사가 붙지 않게 조건을 둔다.
  - 한글 이름(`sector.json` 종목명, DART 고유번호 목록의 법인명): 3자 이상이면 잇는다. 대상 기업 이름에서 그룹 이름을 떼면 같아지는 이름(현대모비스 → 모비스)은 약칭일 수 있어 잇지 않는다.
  - 영어 이름(DART 고유번호 목록): 6자 이상이고 다른 상장사와 겹치지 않을 때만, 언급마다 나라를 보고 잇는다. DART 언급은 나라가 해외로 적히지 않았으면, 뉴스 언급은 한국으로 적혔을 때만 잇는다(중국 자회사 "SHOWBOX Inc."가 쇼박스에, 태국 "Igloo"가 이글루에 붙지 않게).
  - 해외로 적힌 언급이 한글 이름 때문에 후보 밖 상장사로 묶였으면 떼어 낸다. 해외에 본사를 둔 상장사(종목코드 9…)와 국내 법인 표기((주)·㈜)가 있는 이름은 그대로 둔다.
- 한 언급의 한글 이름이 상장사와 같은데 영어 이름 쪽은 상장사가 아니면 한글 이름을 따른다(공시의 "에이텍"에 LLM이 확신 없이 "ATEC"을 붙인 경우). 영어 이름이 그룹 이름(Hyosung, Hanwha)이면 애매로 둔다.
- 그룹 이름만 적힌 언급("Samsung", "포스코")은 묶지 않고 애매로 표시한다(그래프에서 그룹 노드로 잇는다).
- 회사 자신의 지분 표(종속회사·관계기업·출자 대상)에 나온 이름은 그 회사로 묶지 않는다. 모회사와 이름이 같은 자회사(삼성전자의 Samsung Electronics GmbH)는 법인 표기를 살린 이름으로, 똑같이 적힌 것(신도리코의 "SINDOH")은 "(종목코드 자회사)"를 붙여 따로 노드를 만든다.
- **그래프 표기 통일**(2026-11-17): 노드의 나라 이름, 대표 영어 이름, 한글 이름 칸(`name_ko`)을 적는 방식을 하나로 맞췄다. 나라와 대표 영어 이름은 이 절의 아래 두 항목, 한글 이름 칸은 6.4에 있다. 노드 ID와 관계는 바뀌지 않는다.
- **나라는 한글로 적는다**(2026-11-17). DART는 "대한민국", "미국"처럼 한글로, 뉴스 LLM은 "South Korea", "United States"처럼 영어로 적어 같은 나라가 두 가지로 적혀 있었다. 그래서 검색어 만들기가 "대한민국"만 국내로 보고 거른 탓에 뉴스에서 나온 국내 기업 47개(Samsung Electronics, Hyundai Motor, SK hynix 등)가 해외 상대 검색어로 들어갔다. 영어 나라 이름은 대응표로 한글로 바꾸고(여러 나라 "France, Germany"는 나라마다), 대응표는 `source/graph/country_names.csv`로 저장해 그래프 구성(6.4)도 같이 쓴다. 같은 회사로 묶는 일은 바꾸기 전 이름으로 하므로 기업 ID는 달라지지 않는다.
- **대표 영어 이름은 전부 대문자가 아닌 표기를 먼저 쓴다**(2026-11-17). DART 영문 법인명은 "KOREAN AIR LINES CO.,LTD"처럼 전부 대문자인 것이 많아, 다른 언급에 "Korean Air" 같은 표기가 있으면 그것을 대표로 쓴다. 상장사는 DART 영문 법인명이 대문자가 아니면 그대로 쓰고, 대표가 아니게 된 DART 영문 법인명은 다른 이름에 남긴다(검색어 후보가 줄지 않게). 영어 글자 5자 이하 약칭(TSMC, POSCO, HMM)은 대문자여도 그대로 둔다. 다른 표기가 없는 3,741개(대부분 DART에만 나온 해외 자회사·거래처)는 대문자 그대로다.
- **다른 회사가 지배한다고 적은 상장사 이름은 공시끼리 맞춰 본다**(2026-11-17). 회사 A의 지분 표에서 종속회사로 적혔거나 지분 50% 이상인 이름이 다른 상장사 B로 묶였으면, B의 최대주주 표에 A나 A의 계열회사가 있거나, A의 계열회사 현황에 B가 상장 계열회사로 적혀 있을 때만 B로 둔다. 아니면 이름만 같은 다른 회사로 보고 따로 노드를 만든다. B의 최대주주 표가 없거나 최대주주가 투자조합·펀드면 확인할 수 없어 그대로 둔다. 짧은 이름·약칭 때문에 생긴 오류를 잡으려는 것이다: 삼성전자 출자 대상 "TSE"(태국 법인, 91.8%) → 상장사 티에스이, 현대차 출자 대상 "HMM"(99.99%) → 해운사 HMM, DS단석 종속회사 "하이브 주식회사" → 하이브, 에이엔피 종속회사 "(주)우진" → 우진, LS의 "㈜티라로보틱스" → 티로보틱스 등. 결과: 확인돼 그대로 442개, 따로 뗀 언급 18개(회사 11곳), 확인할 수 없어 그대로 12개(대부분 공시를 받지 않은 상장사의 실제 관계: LS티라유텍, 제노코, 코오롱티슈진 등). 지분 50% 미만(넷마블 → 하이브 9.25%)은 A가 최대주주가 아닐 수 있어 확인하지 않는다.
- 결과: 언급 70,607개 → 기업 노드 40,836개(상장사 1,573: DART 기업개황을 받은 1,067 + 언급된 그 밖 상장사 506, 영어 이름 18,840, 한글 이름만 20,423). 서로 다른 상장사를 잇게 되어 막은 연결 5건(한국철강·한국특강·한국파마 영문명). 표기 통일로 나라 2,454개, 대표 영어 이름 585개가 바뀌었다(ID와 언급 → 기업 대응은 그대로).

### 6.3 제품 사전 (`product_dictionary` → `product_llm` → `product_apply`)

DART와 뉴스의 제품·원자재·브랜드 이름을 같은 것끼리 묶고 계층(메모리 > DRAM > HBM)을 만든다. **규칙 버전**(`product_dictionary`)으로 먼저 묶고, **LLM 버전**(`product_llm` → `product_apply`)으로 묶음과 계층을 다시 만들어 그래프에 쓴다.

- 제품·원자재 사전과 브랜드 사전을 나눈다(DART "Steam"은 증기, 뉴스 "Steam"은 게임 플랫폼).
- 정규화: 소문자, 끝의 and others·etc·service·product 제거, "U.S." → US. 대문자 약칭은 2~4자 대문자나 숫자가 섞인 6자 이하(PET, HBM, HBM3E)만 그대로 둬 일반어와 가른다(PET ≠ pet).
- 단수형: 영어 사전(WordNet, 자료는 `source/nltk_data/`에 두고 없으면 노트북이 처음 한 번 받는다)이 아는 명사면 사전의 단수형(cases → case), 복수형 자체가 표제어면 그대로(series, news, Texas), 사전에 없는 단어(smartphones)는 끝의 s를 뗀다. 예외 단어 목록은 두지 않는다. 브랜드 사전은 고유명사라 단수형으로 바꾸지 않고 대소문자도 가리지 않는다.
- 잇는 근거: 정규화한 이름이 같음, 공백만 다른 이름(skin care = skincare), 한 언급의 원래·영어 이름, 검색어. 한 단어·3자 이하 이름은 전체에서 한 제품만 가리킬 때만 잇는다.
- 결과: 제품·원자재 13,767개, 브랜드 5,596개, **뉴스와 DART를 잇는 제품 277개**(원유, LNG, AI 칩, ESS, HBM 등). 상장사 10곳 이상이 만드는 일반적인 제품 94개는 검색어 순위를 낮춘다.
- 규칙 버전은 LLM 버전의 출발점이자, 그래프를 갱신할 때 새 언급을 기존 노드에 맞추는 규칙으로 계속 쓴다. 이름이 같은 다른 제품(웨이퍼–웨하스), 넓은 말로 합쳐진 것(에틸렌 공장 → 에틸렌), 한 칸에 여러 품목이 적힌 이름("레진, 가소제 등"), 표시용 한글 이름은 LLM 버전에서 고친다.
- **LLM 버전**(`product_llm.ipynb`에서 실행하고 원본을 보관, 새 노트북 `product_apply.ipynb`가 결과를 적용). 처음에는 `product_dictionary`에서 적용하려 했으나, 그러면 `product_dictionary`가 LLM 앞뒤로 두 번 돌아 흐름이 되돌아가서 적용 노트북을 따로 두었다(규칙 사전 → LLM → 적용 → 그래프, 한 방향). 대상은 그래프에 쓰이는 제품 12,643개와 브랜드다.

  - 지시문은 시범 묶음(오늘 찾은 섞인 노드·넓은 말·동의어·계층 사례에 정답을 붙인 것)으로 Codex에서 다듬고, 전체는 배치 API로 돌린다.
  - 그래프에서 계층은 하위 → 상위 `SUBTYPE_OF`, 브랜드는 `OF_PRODUCT`로 잇는다. 계층에는 근거 문장이 없으므로 **사용자에게 보이는 경로에서는 업종·테마처럼 "분류"로 표시해** 근거가 있는 관계와 구분한다.
  - 후보 하위 제품은 `candidate=true` 노드로 두고 **검색어로만 쓴다**(경로에는 쓰지 않는다). 뉴스·공시에서 근거가 나오면 일반 관계로 올린다.
  - 성공 기준: 뉴스와 DART를 잇는 제품 수(지금 277개), 시범 묶음 정답률, 후보 하위 제품이 실제 미국 기사 본문에 나오는 비율.
  - 1단계 판단 규칙: 같은 이름이라도 회사·업종으로 볼 때 다른 제품군이면 나누고, 기술·공정·플랫폼은 그 기술이 쓰이는 제품군에, 제약사의 개발 코드명은 적응증을 모르면 "적응증 미상 의약품"에 넣고, 같은 제품을 넓게·좁게 부른 것과 공급망 앞뒤(원재료로 사는 회사와 제품으로 파는 회사, 원료의약품과 완제의약품)는 나누지 않는다. 막연한 이름(CASE, 코드명)만 회사 사업으로 짐작한다. 첫 그룹은 언급이 가장 많은 뜻(보이지 않는 언급이 첫 그룹으로 간다).
  - **적용**(`product_llm` 23절 내보내기 → `product_apply`):
    - 내보내기: 언급마다 1단계 줄번호 → 그룹 → 2단계 제품을 따라가 "원래 언급 → 제품" 표를 만든다. 보이지 않은 줄(노드당 15줄 넘는 것)은 첫 그룹으로 간다. 2단계 번호 오기는 `parent_name`으로 바로잡고, 빠진 그룹은 제품군 바로 아래 제품으로, 2단계에 보내지 않은 그룹(기타·시장 지표·가격 지표)은 그룹마다 평평한 제품으로 둔다.
    - ID: 제품 `P:소문자 영어 이름`(여러 제품군에 같은 이름이면 `P:제품군/이름`), 제품군 `PF:key`, 후보 하위 제품 `PC:`, LLM 결과 전 임시 제품 `PR:규칙 키`.
    - LLM 결과가 없는 언급은 규칙 노드로 대신 잇는다. 그 규칙 노드의 다른 언급이 모두 한 제품으로 갔으면 그 제품, 아니면 규칙 노드를 임시 제품(`pending_llm`)으로 둔다.
    - 검색어(임시): 영어 이름, 언급의 영어 표기(여러 품목 언급은 빼고), 규격, 통째로 들어온 규칙 노드의 검색어. 검색어 노트북이 다시 고른다.
    - **브랜드 → 제품**: 브랜드 언급에 3단계 결과를 붙여 브랜드 노드마다 이을 제품(없으면 제품군)을 모은다. 같은 브랜드가 회사마다 다른 제품이면 여러 개(HYUNDAI → 굴착기·지게차), 어떤 제품에 이어졌으면 그 제품군으로만 이은 것은 뺀다. 결과: 브랜드 5,596개 중 4,818개를 이음(제품 4,203, 제품군만 615), 관계 4,975개. 결과가 없는 브랜드 언급(관계에 쓰이지 않은 뉴스 866개)은 잇지 않는다. 예: Zepbound·Mounjaro·Ozempic·Wegovy → GLP-1 수용체 작용제(국내 제조사 4곳), 신라면 → 라면.
    - 결과: 제품 언급 23,127개 중 LLM 21,156 / 규칙 노드로 대신 584 / 임시 1,387(모두 관계에 쓰이지 않은 뉴스 언급). 노드는 제품군 273, 제품 11,693(중간 제품 160), 후보 2,659, 임시 1,144. 여러 품목 언급 684개는 제품 여러 개로 간다. **뉴스와 DART를 잇는 제품은 직접 295개**(규칙 277개), 계층을 거치면 1,399개가 더 이어진다.
  - 1단계 결과는 v4를 쓴다(`stage1_groups_product_node_v4.csv`). 알려진 한계: 모음 묶음과 구체 묶음의 범위가 겹쳐, 구체 묶음이 있는데 모음 묶음으로 간 그룹이 약 100개(언급 0.6%) 있다(철 합금 FC250D·Invar → 산업용 금속). 이런 것은 해당 제품군 계층에 들어가지 못한다.
  - LLM이 긴 목록에서 노드를 드물게 건너뛰므로(1단계 12,643개 중 1개) 결과에 없는 노드는 다시 보낸다. 노드 수와 예상 비용(일반 요청 / 배치)을 보여 주고 사용자가 고른 방식으로만 보낸다.
  - 제품군 검토 내용(합치기, 새로 만들기, 이름·범위 고치기, 모음 표시)은 코드가 아니라 **검토표 `review/family_review.csv`**에 둔다. LLM은 같은 지시문에도 실행마다 다른 제품군 이름을 낼 수 있어서, 처음부터 다시 돌리면 이 검토표가 맞지 않을 수 있다. 노트북은 맞지 않는 곳에서 멈추지 않고 알리며(이번 결과에 없어 적용하지 않은 합치기, 검토표에 없는 새 제품군), 알림이 나오면 LLM 결과를 직접 검토해 표를 고친 뒤 다음 단계로 넘어가기를 권한다. 시범 사례·정답 확인도 데이터에 없는 이름은 건너뛰고 알린다.
  - 제품군 확정 때 정한 것: 같은 주제는 제품·서비스·시설로 나누지 않는다(AI, 게임, 데이터센터, 전력, 충전소 운영, 통신 장비). 다만 충전 **장비**는 만드는 회사가 달라 따로 둔다. 소프트웨어는 용도별(기업용, 보안, 산업·설계, 의료). 특정 제품의 가격은 그 제품군에 붙이고(메모리 가격 → 메모리 반도체), 어느 제품에도 붙지 않는 물가·금리·주가지수·운임은 "시장·경제 지표" 하나로. 넓은 모음 묶음 4개(산업 설비·공구, 산업용 금속·범용 부품, 산업용 화학 원료·첨가제, 기타)는 구체적인 제품군에 넣을 수 없을 때만 쓴다.

**규칙**

- 업종·테마 소속은 서비스 대상 후보 951개에만 붙인다. 후보 밖 상장사는 다른 기업과 관계가 있을 때만 일반 기업 노드로 두고, 업종·테마는 속성으로만 남긴다.
- 그룹 소속은 공시(계열회사 현황)에 근거한 관계라 그래프에 남은 기업 노드 모두에 붙인다(후보, 후보 밖 상장사, 비상장 계열사). 그룹 소속만으로는 노드를 남기지 않는다.
- 기업·제품·브랜드·정책·기관·시설·프로젝트 노드는 관계(소속 제외)가 하나 이상 있을 때만 둔다. 서비스 대상 후보는 관계가 없어도 둔다. 그래프는 매번 처음부터 다시 만들므로, 나중에 관계가 생기면 그때 노드가 생긴다(이름은 이름 통일 표와 제품 사전에 남아 있어 같은 ID로 묶인다).
- 후보 밖 상장사와 같은 회사인 언급은 이름 통일이 `KR:종목코드`로 잇는다(6.2). 두 글자 이하 이름(삼진, 서한 등)과 같은 한글 노드는 잇지 않고 `maybe_listed`로 표시만 한다.
- **노드 ID는 빌드마다 데이터로 다시 정해진다.** 상장 폐지·합병으로 `sector.json`에서 빠진 회사는 다음 빌드에서 `KR:` 대신 `EN:`·`KO:` ID가 되고, 영어·한글 대표 이름이 바뀌면 `EN:`·`KO:` ID도 바뀐다. 그래서 그래프 밖에 저장하는 것(사용자 보유 종목, 검색어 결과 등)은 노드 ID가 아니라 종목코드로 저장하고, 서비스 대상은 ID 앞부분(`KR:`)이 아니라 `target` 속성으로 찾는다.
- 그룹은 사업보고서 계열회사 현황으로 정한다. 보고 회사와 그 목록의 상장 계열회사를 같은 그룹으로 묶고(기업집단 이름은 엘지·LG계열처럼 표기가 달라 묶는 데 쓰지 않는다), 상장 계열회사가 2개 이상인 것을 그룹 노드로 둔다. 비상장 계열회사는 DART 언급 이름이 한 기업 노드만 가리킬 때 잇는다. 근거는 그 사업보고서다("계열회사 현황(상세): 기업집단 삼성, 삼성디스플레이(주)").
- 그룹 이름만 적힌 언급("Samsung", "현대")은 그룹 노드로 잇는다. 이런 그룹 18개(삼성, SK, 현대차, 금호 등)는 대표 상장사로 계열회사 현황의 그룹과 맞추고, 상장 계열회사가 하나여도 둔다(금호석유화학).
- **`name_ko`에는 한글이 들어간 이름만 둔다**(2026-11-17). 한글 이름이 없어 영어를 그대로 적었던 제품 823개(코드명 "GC1134A" 등)와, 뉴스 정책·기관·시설·프로젝트 노드의 기사 속 영어 표기 1,119개("factory in Shanghai")는 `name_ko`를 비운다. 기사 속 영어 표기가 대표 이름과 다르면 다른 이름(`other_names`)에 남긴다. 상장사는 거래소 종목명을 그대로 둔다(NAVER, CJ 등 53개는 영어지만 국내 공식 이름이다). 나라(`country`)도 한글로 적는다(6.2의 대응표).
- 지분 관계에는 출자 목적을 남겨, 경로를 찾을 때 단순투자 지분을 거를 수 있게 한다.
- 여러 품목이 적힌 언급("레미콘, 이형철근")은 제품마다 관계를 만든다(생산·구매, 매입처 공급의 `product`, 뉴스 관계).
- 제품 노드도 관계가 있을 때만 두되, 남은 브랜드가 가리키는 제품·제품군, 남은 제품의 상위 제품·제품군과 후보 하위 제품은 함께 남긴다(`OF_PRODUCT`, `SUBTYPE_OF`). 계층·브랜드 연결만으로는 노드를 남기지 않는다.

**기사와 공시는 노드가 아니라 관계의 근거다.** 뉴스는 공시에서 찾기 어려운 관계를 더 뽑아내는 자료로 쓰고, 기사·사건 자체는 그래프에 넣지 않는다.

- 관계마다 근거 문장(`evidence`)과 그 출처(`evidence_refs`)를 같은 순서로 붙인다(최근 것부터 최대 3개, 출처마다 하나, 같은 문장이 여러 기사에 나오면 가장 최근 기사 하나만. 기사 수와 기사 목록에는 모두 남는다). 출처는 기사면 `A:기사ID`, 공시면 `D:접수번호`다. 지분 관계는 표 한 줄이라 "반기보고서 (2026.06) 출자 대상 표: ○○"처럼 적는다.
- 출처 목록은 그래프 밖에 둔다(`source/graph/sources/`): `articles.csv`(근거로 쓰인 기사 1,865건: 제목, 매체, 링크, 발행 시각), `filings.csv`(공시 2,156건: 회사, 보고서, 기준일, DART 링크).
- 사용자에게 연결을 보여 줄 때 "이 관계는 어느 공시·기사에서 나왔다"를 함께 보여 주는 데 쓴다(예: SK하이닉스 → 공급 → Nvidia, Fortune 2026-11-10 기사).

**결과**(LLM 제품 사전 적용 후, 대상 951개 기준): 노드 61,720개, 관계 111,663개(지분 39,779, 생산 15,688, 제품 계층 14,351, 그룹 소속 6,569, 공급 6,465, 구매·사용 6,074, 브랜드 4,998, 브랜드 → 제품 4,975 등). 끝점을 못 찾아 빠진 관계는 0이다.

- 확인한 경로: HBM ← 생산 삼성전자·SK하이닉스(DART+뉴스)·마이크론(뉴스), HBM → DRAM → 랜덤 액세스 메모리 → 메모리 반도체(분류), Zepbound → GLP-1 수용체 작용제 ← 펩트론·보령·콜마홀딩스·팜젠사이언스(DART), ABB Robotics의 IRB 로봇 → 다관절 로봇 ← 로보스타·유일로보틱스, 방산 테마 ← 한화에어로스페이스(업종은 상사,자본재).

### 6.5 검색어 (`search_terms.ipynb`)

서비스 대상 후보 951개 **모두**의 구글 뉴스 RSS 검색어를 그래프를 다시 만들 때마다 미리 만들어 종목코드 기준 표로 내보낸다(**지금 상태**: 규칙과 기본 검색어를 만들었고, 2026-11-17 지금 규칙 그대로 **전체 표**를 내보냈다(`search_terms` 12절, `source/search/queries_all.csv`). 같은 날 그래프 표기를 통일하고(6.2, 6.4) 대상을 951개로 바꾼 뒤(2장) 다시 만들었다. 밤사이 수집은 아직 시험 종목 17개(검색어 169개)의 임시 표를 쓰고, 검색어를 줄이는 규칙(결정할 것 #22)을 정한 뒤 전체 표로 바꾼다). 구글 뉴스 RSS 검색은 이 표에서 보유 종목의 검색어만 골라 중복 없이 한 번씩 검색하고, 찾은 기사는 검색어 → 종목 대응으로 돌려준다. 정확도는 매일 밤 프롬프트가 맡고, 검색은 정해진 예산 안에서 넓게 잡는다.

- **검색어 종류와 모양**(모든 종목 공통):

  | 종류 | 모양 | 예 |

  | 구체 제품 | 주제만 | "high-bandwidth memory" |
  | 브랜드 | 이름만(미국 뉴스에 나오는 것 위주) | "Shin Ramyun" |
  | 해외 상대(고객·공급사·경쟁사·파트너) | 이름만. 기사가 쏟아지는 대형사(Nvidia, Microsoft)도 그대로 검색하고, 관련 여부는 밤사이 프롬프트가 그래프 연결 근거로 가린다 | "Novo Nordisk", "Nvidia" |
  | 원자재·지표, 정책 | 주제만 | "jet fuel", "steel tariffs" |
  | 테마 공통 | 테마 기본 검색어(LLM) + 테마 대표 검색어(같은 테마 종목의 제품·해외 상대 중 미국 뉴스에 자주 나온 것) | "defense spending", "memory prices" |

- **종목 유형**: 업종을 6개 유형으로 묶고, 유형은 검색어 종류마다 몇 개씩 줄지(종목당 상한 안에서)를 정한다. 테마 125개도 같은 유형에 대응시키고, 사업 내용을 말해 주지 않는 테마(지주사, 무역, 유통, IT, 경영지원, 컨택센터)는 중립으로 둔다. 유통은 소비재 유통과 부품·원료 유통(반도체 유통상)이 섞여 중립이다.

  | 유형 | 업종 | 우선 검색어 |
  |---|---|---|
  | 제품·공급망 | 반도체, 자동차, 화학, 기계, IT하드웨어, IT가전, 디스플레이, 소프트웨어 | 구체 제품, 해외 상대 |
  | 의약·바이오 | 건강관리 | 약효군·적응증, 해외 제약 파트너, 경쟁 약 브랜드 |
  | 브랜드·소비자 | 화장품,의류, 필수소비재, 미디어,교육, 소매(유통), 호텔,레저 | 브랜드, 구체 제품 |
  | 수주 | 건설, 상사,자본재, 조선 | 발주 분야, 발주처·해외 상대, 정책 |
  | 원자재·가격 | 비철금속, 철강, 운송, 에너지, 유틸리티 | 원자재·지표, 정책 |
  | 금융·거시 | 증권, 은행, 보험, 통신서비스 | 자기 회사(거시는 매일 밤 프롬프트의 "시장 전체") |

- **업종이 실제 사업과 다를 때**: 기본 유형은 업종 유형이다. 테마(중립 제외)가 모두 한 유형이고 업종 유형과 다르면 기본 유형을 테마 유형으로 바꾼다(게임사: 소프트웨어 → 브랜드·소비자). 그 밖에 테마가 가리키는 다른 유형은 보조 유형으로 더한다(삼성전자: 제품·공급망 + 스마트폰·가전 테마로 브랜드·소비자). 그래프 연결로도 더한다(브랜드 5개 이상 → 브랜드·소비자, 수주 관계 5개 이상 → 수주).
- **연결이 적은 종목**: 미국 뉴스에 나온 검색 재료(만드는 제품과 그 위 계층 2단계, 브랜드의 제품, 해외 상대 중 미국 뉴스 기사 수가 1 이상인 것)가 1개 이하인 종목은 검색어를 테마 쪽으로 더 준다. 테마 검색어는 테마마다 한 번만 검색해 같은 테마 종목이 함께 쓰므로 검색 수가 늘지 않는다. 테마로 찾은 기사는 연결이 약하므로 "테마 관련 뉴스"로 따로 표시하고 순위를 낮춘다(경로: 회사 → 테마 → 기사).
- **1단계 결과**(`source/search/company_types.csv`, 대상 951개): 기본 유형 제품·공급망 326, 브랜드·소비자 203, 원자재·가격 158, 수주 113, 의약·바이오 88, 금융·거시 63. 테마로 기본 유형을 바꾼 종목 78개, 보조 유형이 있는 종목 395개. 연결이 적은 종목 583개(61%, 금융·거시 84%, 브랜드·소비자 71%, 제품·공급망 60%, 수주 58%, 의약·바이오 56%, 원자재·가격 49%). 국내 거래처(삼성전자, 현대차 등)는 해외 상대 재료로 세지 않는다. 지금 쌓인 기사가 2,471건뿐이라 기사가 늘면 줄어든다. 연결이 적은 종목인지는 아직 검색어 수에 쓰지 않는다(검색어 표의 `weak` 칸에만 적는다).
- **업종·테마 기본 검색어**(LLM): 업종 26개와 테마 113개(중립·종목 없는 테마 제외)마다 산업·시장 수준의 미국 뉴스 검색어 3~5개를 **중요한 순서로**. 입력은 대표 종목, 그 묶음에 몰린 대표 제품, 미국 뉴스에 나온 제품. 지시문 `search_base_v4`: **2단어 기본, 꼭 필요할 때만 3단어, 4단어 이상 금지**(검색은 따옴표로 표현 그대로 찾아 길면 안 잡힌다). 묶음 이름이 가리키는 사업을 기준으로(대표 제품은 넓은 이름을 좁히거나 모호한 이름을 이해하는 데만, 종목의 다른 사업은 회사 검색어가 맡음), **한국 종목에 이어지는 경로가 있는 뉴스만**(한국 종목이 파는 것의 수요, 사고파는 것의 세계 가격, 미국·국제 정책, 세계 경쟁사). 미국 국내만의 지표(미국 주택 착공)는 한국 종목이 미국에 그것을 팔 때만. 너무 넓은 말·고유 이름 금지. 일회성 소량 작업이라 Codex 구독 **`gpt-6.1-sol` + 추론 high**(요청 3건, 약 4분). 결과 139개 중 134개에 검색어, 평균 1.99단어(반도체: DRAM prices, HBM demand, NAND prices / 건설: Saudi megaprojects, LNG projects / 화장품,의류: K-beauty, apparel tariffs). 5개는 사업이 섞였거나 미국 뉴스 경로가 약해 비움(상사,자본재, 금융, 부동산신탁, 부동산임대개발, 여가생활). `source/search/base_terms.csv`. 같은 지시문으로 다시 돌려도 검색어는 절반 정도만 같다(표현이 여럿 가능). 2026-11-17 그래프 표기 통일과 대상 951개 변경 뒤 다시 돌린 결과(업종 26개, 테마 112개): 비운 것 5개(상사,자본재, 금융, 부동산신탁, 부동산임대개발, 여가생활). 반도체 → DRAM prices, HBM demand / 소매(유통) → duty-free sales, Chinese tourists / 은행 → Treasury yields, dollar funding.
- **회사 단위 기본 검색어**: 업종·테마 기본 검색어를 하나도 못 받는 종목(업종·테마가 모두 비었거나 중립) 5개(v3 기준일 때 11개)는 회사 하나를 입력으로(업종, 테마, 주요 제품, 브랜드, 주요 자회사·투자 대상, 미국 뉴스에 나온 해외 상대·제품) 같은 원칙의 검색어를 만든다. 지주사·상사는 큰 사업 2~3개에 나눠 적는다. 지시문 `search_company_v2`(업종·테마와 같은 2단어 규칙), `gpt-6.1-sol` + high, 요청 1건. 4개에 검색어(LX홀딩스 → freight rates, display chips, MMA prices / KTcs → call centers, conversational AI / 현대지에프홀딩스 → resin prices, food prices, luxury spending), 공시 데이터가 없는 신규 상장사(한화머시너리앤서비스홀딩스)는 비움. `source/search/company_base_terms.csv`. 2026-11-17 대상 951개로 다시 돌린 결과: 대상 5개(현대지에프홀딩스, 한화머시너리앤서비스홀딩스, KTcs, KTis, LX홀딩스) 중 4개에 검색어(LX홀딩스 → freight rates, resin prices, display driver ICs / KTcs·KTis → call centers, AI agents / 현대지에프홀딩스 → food prices, resin prices), 한화머시너리앤서비스홀딩스는 비움
- **검색어 후보 규칙**(구글 뉴스 RSS 2·3차 시험으로 정함):
  - 모양은 이름만·주제만. "회사 + 주제"는 88%가 0건이라 쓰지 않는다. 3단어 이상 주제를 따옴표 없이 검색하면 기사는 늘지만 대부분 상관없는 기사라 쓰지 않는다(긴 검색어는 짧게 줄인다).
  - **일반 영어 한 단어는 뺀다**: 영어 사전(WordNet)에 있는 한 단어(juice, drones, documentaries, ACROSS)는 상관없는 기사가 하루 수백 건씩 걸린다. 약칭(대문자 4자 이하: HBM, LNG, DRAM), 원자재·지표(nickel, ethanol), 회사 이름(Apple, Shell)은 둔다. 빠진 자리는 다음 순위 후보가 채운다.
  - **3자 이하 회사 이름은 긴 이름**: LX(→ Lexus LX), GKL, GM은 다른 뜻·회사와 겹친다. 긴 이름(Grand Korea Leisure, General Motors), 짧은 것뿐이면 Holdings·Group을 남긴 이름(LX Holdings), 그것도 없으면(TFE) 그대로.
  - **테마 대표**: 그 테마 종목이 만드는 비율(집중도) 0.4 이상, 3단어까지(일반어를 빼자 화장품·음식료 테마에 GLP-1(집중도 0.18)이 올라왔다).
  - 실행마다 결과가 같게 정렬한다(해외 상대를 집합 순서로 뽑아 LLM 입력이 매번 달라지던 것을 고침).
  - 해외 상대는 나라가 비었거나 "대한민국"인 기업을 뺀다. 그래프 표기 통일(2026-11-17) 전에는 뉴스에서 온 국내 기업이 "South Korea"로 적혀 해외 상대에 들어갔다.
- **LLM 기본 검색어는 입력이 바뀌면 다시 만든다**: 노트북은 LLM 입력 글 전체의 지문(해시)을 실행 기록(`source/search/llm/runs.csv`)에 남기고, 다음 실행 때 지문이 같을 때만 저장된 결과를 쓴다. 입력이 한 글자라도 바뀌면 결과를 쓰지 않으므로, `RUN = False`인 채로 그래프만 다시 만들면 업종·테마·회사 기본 검색어가 검색어 표에서 모두 빠진다. 2026-11-17 그래프 표기 통일 때 대표 종목의 영어 이름 표기("SAMSUNG ELECTRONICS" → "Samsung Electronics")만 바뀌었는데도 이렇게 되어(약 5,100줄 빠짐), 그래프와 함께 LLM도 다시 돌렸다(Codex 요청 4건). 대상을 951개로 바꿨을 때도 업종·테마의 대표 종목이 바뀌어 다시 돌렸다.
- **검색어 후보**(시험용 규칙): 구체 제품은 직접 만드는 것 2개 + 위 계층 중 미국 뉴스에 나온 것 1개(코드명은 미국 뉴스에 나온 것만), 넓은 제품 1개, 브랜드는 소비자·의약 유형이 아니면 미국 뉴스에 나온 것만, 해외 상대는 대표 영어 이름(MS·GM 같은 짧은 별칭 금지), 원자재는 넓은 것 제외, 테마 대표는 테마 집중도로 순위(집중도가 없으면 지주사·대기업 제품이 여러 테마에 올라옴).
- 검색 방식, 기사 아닌 페이지 거르기, 밤사이 처리 흐름, 검색어 규칙의 근거가 된 구글 뉴스 RSS 시험은 `news_search/news_search.md`에 있다.

### 6.6 검색어 연결표 (`term_links.ipynb`, 2026-11-20 정함)

- 검색어 표의 줄마다 그 검색어가 종목과 그래프에서 어떻게 이어지는지(관계 종류·내용·금액·근거 문장 2개까지)를 붙인 표. 뉴스 상세 "예상과 밤사이 소식, 같이 읽기"에서 **기사가 어떤 경로로 내 종목과 이어졌는지** 설명하는 문장을 LLM이 쓸 재료다.
- 서버에는 그래프 DB(Neo4j)를 올리지 않는다. 이 설명에 필요한 것은 기사와 상관없이 정해진 "종목–검색어" 관계뿐이라 표 하나로 충분하다.
- 결과: `source/search/term_links.csv`, 서버 DB `news.term_links`(키: 종목코드·종류·검색 문자열·노드, 통째로 바꿈). 기사와는 수집 DB `hits.term` = `term_links.query`로 잇는다. 검색어 표를 다시 만들면 이 노트북도 다시 돌린다.
- 연결 방식: 제품·브랜드·원자재·해외 상대는 두 노드 사이 관계(direct), 자기 회사·회사 기본은 종목 자신(self), 업종 기본은 소속 업종(sector), 테마 기본은 소속 테마(theme), 직접 관계가 없는 테마 대표는 그 테마 소속(theme_product).
- 2026-11-20 결과(951종목, 11,407줄): direct 3,773(모두 근거 문장 있음), sector 1,822, theme 2,772, theme_product 1,611, self 1,066, none 363(정책 107 전부 · 구체 제품 162 · 넓은 제품 94. 정책은 종목에 바로 잇지 않고 제품·업종을 거쳐 이어져 있어서).
- 한글 이름(`name_ko`, 2026-11-21 정함): 종목과 이어진 것들을 그림으로 보여 줄 때 칸에 적을 짧은 한글 이름. 자기 회사는 종목 이름, 나머지 검색어 2,706개는 LLM으로 한 번 번역해 `source/search/term_names_ko.csv`에 쌓는다(이미 있는 검색어는 다시 번역하지 않음, 지시문 `prompts/term_name_ko_v1.md`, gpt-6.1-terra, 약 $0.3). 서버 표는 이 칸만 채운다(`RUN_NAME_UPLOAD`). 한국 표기가 없는 브랜드·제품 이름은 원문 그대로다.

## 7. 실험 기록

규칙과 선택을 정할 때 한 실험이다. 무엇을 어떻게 시험했고, 결과를 보고 무엇을 정했는지만 짧게 남긴다.

LLM 추출은 모두 같은 순서로 시험했다: **시범 문서를 고정 → Codex 구독으로 지시문 버전을 올리며 비교 → 최종 지시문을 API로 20건 확인 → 배치로 전체 추출.** 결과는 근거 문장과 원문을 대조해 판단했다.

**수집**

| 실험 | 방법 | 결과 → 정한 것 |
|---|---|---|
| 봇 보호 매체 요청 간격 | 같은 매체 기사 페이지를 3초·30초 간격으로 요청 | 30초에서 훨씬 덜 막힘(Industry Dive 약 70% 성공) → 기사 페이지는 같은 서버에 60초 간격 |
| 본문 수집 가능 여부 | 후보 매체마다 기사 10~20건을 받아 RSS 요약·제목과 내용 대조(단어 수만 보면 사이드바를 본문으로 잘못 셈) | 유료·회원 전용·봇 차단 매체 확인 → 쓰지 않는 매체 표(4.3) |
| 사업보고서 원문 받기 | 최신 보고서만 검색해 받기 | `[첨부정정]` 39개 기업의 본문이 빠짐 → 정정 전 보고서까지 찾아 본문이 있는 최신본을 받음 |

**DART**
