# 그래프 DB 구축 요약

최종 수정: 2026-11-16 12:35 (KST) · 자세한 내용과 결정 근거는 `graphDB.md`에 있다.

## 1. 무엇을 만드는가

서비스는 한국 아침에 **밤사이 미국에서 나온 뉴스 중 사용자 보유 종목과 관련된 것**을 골라 보여 준다. 그래프 DB는 국내 기업과 해외 기업·제품·사건을 잇는 지도이고, 두 가지에 쓴다.

1. **검색어 만들기**: 밤사이 구글 뉴스 RSS로 미국 뉴스를 찾을 영어 검색어를 만든다.
2. **연결 경로 보여 주기**: 뉴스가 어떤 경로로 보유 종목과 이어지는지 보여 준다.
   예: 보유 종목 SK하이닉스 → 주요 고객 Nvidia → Nvidia 실적 뉴스

관계마다 **종류, 근거 자료(공시·기사)와 근거 문장, 시점**을 함께 남겨, 사용자에게 보여 주는 경로를 원문까지 거슬러 확인할 수 있게 한다.

## 2. 연결은 어디서 오는가

| 연결 | 예 | 출처 | 이유 |
|---|---|---|---|
| 지분·계열 | LG에너지솔루션 ↔ Ultium Cells(GM 합작사) | 국내 공시(DART) 지분 표 | 법적 실명 공개 대상이라 정확하다. 미국 뉴스는 한국 모회사보다 현지 법인·합작사 이름으로 나온다 |
| 제품·고객·매입처·경쟁 | 삼성전자 → HBM, 한미반도체 → 고객 Micron | DART 사업보고서 "사업의 내용"(LLM 추출) | 국내 기업이 무엇을 만들고 누구와 거래하는지 |
| 공급망·사건 | Doosan Enerbility → NuScale 원자로 부품 수주 | 미국 뉴스(LLM 추출) | 공시에서 익명("A사")인 상대가 뉴스에는 실명으로 나온다 |
| 업종 | 미국 반도체 업황 → 반도체 업종 국내 기업 | WI26 업종 분류(26개) | 관계가 뚜렷하지 않은 기업도 업종 뉴스로 잇는다 |
| 테마 | 방산 테마 → 한화에어로스페이스·LIG디펜스앤에어로스페이스·풍산 | 토스증권 테마(125개) | 업종보다 사용자에게 익숙한 이름. 방산 종목은 WI26에서 8개 업종에 흩어져 있다 |

국내 기업과 해외 기업은 직접 관계가 없어도 **제품 노드를 거쳐** 이어진다(SK하이닉스 → HBM ← Micron·Nvidia).

## 3. 전체 흐름

```
[국내 공시: OpenDART]                       [미국 뉴스: 공식 RSS 상시 수집]
 dart_targets → dart_collector               news_collector (윈도우 PC, MySQL 공유 DB)
        │                                            │
        ├─ dart_parser ─────── 지분·계열 표           news_filter ── 뉴스가 아닌 글 거르기(규칙)
        │                                            │
        └─ dart_business_parser ─ LLM 입력 글 + 표    news_extractor ── LLM 추출
                │                                    │
           dart_business_extractor ── LLM 추출        │
                │                                    │
           dart_business_cleaner ── 최종본            (정리 → 최종본)
                └──────────────┬─────────────────────┘
                    이름 통일 → 제품 사전 (이름·계층 통일)
                               │
                           그래프 DB (Neo4j)
                               │
                 검색어 (search_terms) → 구글 뉴스 검색·처리 (news_search/)
```

원칙: **단계마다 결과를 따로 저장**한다. 규칙 단계(거르기·정리)는 자주 고쳐 다시 돌리고, 비용이 드는 LLM 단계는 한 번 돌린 원본을 보관해 다시 돌리지 않는다.

## 4. 대상 기업

- **서비스 대상 후보**: **1,067개**(`source/targets.csv`, 코스피 전체 801 + 코스닥150 + 코스닥 추가 116). 서비스할 수 있는 종목의 최대 범위로, 이 목록에 없는 종목은 서비스 대상이 되지 않는다. 우선주·리츠·인프라펀드·해외 기업·스팩·관리종목은 뺀다.
- **실제 서비스 대상**: 이 안에서 고른다(코스피200 + 신뢰할 만한 코스닥 기업 일부, 야간선물 기반 시가 예측 파트와 같은 대상).
- 모든 기업을 **WI26 26개 업종** 중 하나로 분류해 두었다.
- **토스증권 테마 125개**(예: 방산·반도체·이차전지)도 함께 붙인다. 더 세부적인 연결은 제품 사전이 맡는다. 그래프에서 업종·테마는 서비스 대상 후보에만 붙인다.

## 5. 국내 공시

### 5.1 지분·계열 (`dart_parser`)

OpenDART 공식 API(무료, 하루 2만 건)로 기업마다 **가장 최근 정기보고서**에서 받는다. 지분 관계는 실명이 공개되므로 그대로 쓴다.

| 표 | 내용 | 줄 수 |
|---|---|---|
| 종속회사 | 이 회사가 지배하는 회사(해외 법인 포함, 주소·나라) | 19,236 |
| 관계기업·공동기업 | 20% 이상 가진 회사(합작사, 소재 국가) | 8,357 |
| 타법인 출자 | 그 밖의 출자(단순투자는 그래프에서 뺀다) | 19,936 |
| 최대주주 | 누가 이 회사를 가졌나(해외 모회사) | 9,101 |
| 양수도·합병·분할 결정 | 정기보고서 사이의 지분 변화 | 175 |

모든 줄에 공시 접수번호를 남겨 DART 화면을 바로 열 수 있다. 갱신은 월 1회, 새로 올라온 공시가 있는 기업만 다시 받는다.

### 5.2 사업의 내용 (DART 사업보고서 II장)

| 단계 | 노트북 | 하는 일 |
|---|---|---|
| 입력 만들기 | `dart_business_parser` | 제품·원재료·판매경로·주요계약·시장점유율·경쟁 부분만 잘라 회사별 입력 글을 만든다(전체 약 1,140만 자, 회사당 중앙값 약 8,100자). 매출 비중·원재료·매입처·사업장 표는 **규칙으로** 바로 읽는다 |
| LLM 추출 | `dart_business_extractor` | 회사 하나 = 요청 하나. 제품(본문에만 있는 세부 제품 포함), 영어 이름·검색어, 브랜드, 실명 매입처·고객·경쟁사, 시장점유율, 계약, 가격 변동 항목 |
| 최종본 | `dart_business_cleaner` | 회사별 원본 결과를 하나로 합치고 규칙으로 고친다(근거 원문 대조, 자기 자신·지분 관계 중복·재개발 조합 같은 국내 사업장 단위 상대 제거, 띄어쓰기·중복 정리). 고친 내용은 모두 변경 기록에 남긴다 |

**결과(1,063개 회사 완료)**: 제품 13,739, 브랜드 5,015, 원재료 5,253(실명 매입처 4,046), 고객 2,979, 경쟁사 1,688, 계약 3,526. 매출 숫자는 LLM이 아니라 규칙으로 읽은 표를 쓴다.

## 6. 미국 뉴스

### 6.1 수집 (`news_collector`)

- **언론사 공식 RSS로만** 받고, 본문은 RSS에 없으면 기사 페이지에서 추출한다. robots.txt를 지키고 유료벽·봇 차단은 우회하지 않는다.
- 일반 경제 매체 4곳(CNBC, Fortune, CBS MoneyWatch, LA Times)은 1분마다, **업종별 전문지 약 60곳**(WI26 업종마다 1~4곳, 예: 반도체 Semiconductor Engineering, 조선 Maritime Executive·Splash247, 전력 World Nuclear News)은 15분마다 받는다. 전문지는 국내 주력 제품을 다루는 해외 기업 소식과, 공시에서 익명인 고객·공급사의 실명이 나온다.
- 약관이 AI 수집·이용을 명시적으로 금지하는 곳, 평판이 약하거나 후원 기사 비중이 높은 곳은 쓰지 않는다. 기사 표현은 재배포하지 않고 **정해 둔 사실 정보만** 뽑는다.
- 윈도우 PC에서 상시 실행하고, 기사는 공유 MySQL에 쌓는다. 차단·오류는 텔레그램으로 바로 알린다.

### 6.2 거르기 (`news_filter`)

후원·광고, 영상·팟캐스트, 시세 페이지, 생활·커리어, 기고, 행사 안내, 오래된 기사(90일), 중복을 주소·태그·제목 규칙으로 거른다. 본문을 받지 못한 기사(유료벽·차단)는 제목과 RSS 요약만 쓴다. 현재 스냅샷 2,725건 중 **2,471건**을 쓴다.

### 6.3 LLM 추출 (`news_extractor`)

기사 하나 = 요청 하나. 기사 종류와 관련 업종, **개체**(기업·제품·원자재·정책 등과 영어 이름·검색어·나라), **관계**(주체–역할–대상, 매개 제품, 금액, 상태, 확실성), **사건·지표**(실적, 가격 변동, 정책, 공급 차질 등과 우리말 한 줄 설명, 방향 +/−)를 뽑는다. 정치·사건사고처럼 관련 없는 기사는 LLM이 걸러 낸다.

**결과(2,471건, 최종 지시문 v5)**: 개체 19,029, 관계 7,900, 사건 4,262. 관련 없는 기사 82건, 국내 기업 개체 206개. 맞는 역할이 없어 "기타"로 남은 관계는 3.1%다.

## 7. LLM 추출 방식 (DART·뉴스 공통)

**판단 원칙**
- 문서에 **적힌 사실만** 뽑는다. 지식으로 보태는 것은 영어 이름·검색어·범주뿐이다.
- 모든 항목에 **근거 문장을 원문 그대로** 붙인다. 근거가 원문에 실제로 있는지 기계로 대조한다(지어낸 관계를 걸러 냄).
- **실명만** 쓴다("A사", "a major automaker"는 뽑지 않는다). 제품 이름으로 회사를 추정하지 않는다("HBM 공급사"를 SK하이닉스로 바꾸지 않는다).
- 관계는 문장이 두 대상 사이의 역할을 직접 말할 때만 만든다. 단순 나열이나 함께 오른 주가는 관계가 아니다.

**그래프 재료의 틀**
- 노드 8종: 기업, 제품·기술, 상품·브랜드, 원자재·지표, 프로젝트·계약, 시설, 정책·규제, 기관
- 관계 15종 + 기타: 공급, 구매·사용, 생산, 수주·발주, 인수·투자, 매각, 합작·제휴, 라이선스, 경쟁, 규제·인허가, 시설 건설·운영, 영향(+/−), 소송·분쟁, 자금 지원, 정책 입장. 맞지 않으면 "기타 + 설명"으로 남긴다.
- 이름은 원문 표기, 영어 표준 이름, 미국 기사가 쓰는 검색어, 한 단계 위 범주를 함께 남긴다.

**요청과 응답**: 지시문(우리말) + 입력 글을 보내고, 정해진 JSON 스키마(엄격 모드)로 받는다. 형식 오류는 나지 않는다. 지시문과 스키마는 `prompts/`에 있다(`dart_business_v5`, `news_v5`).

**원본 보관**: LLM 응답은 문서별 파일로 받은 그대로 보관하고 고치지 않는다. 이름 통일·제품 사전·그래프는 이 원본에서 언제든 다시 만든다. 실행마다 기록(문서, 입력 해시, 지시문 버전, 모델, 토큰, 비용)을 남겨, 다시 돌릴 문서를 고를 수 있다.

## 8. 실행 수단과 비용

| 작업 | 수단 | 실제 비용 |
|---|---|---|
| 지시문 다듬기(시범 문서로 반복) | ChatGPT 구독 Codex(`gpt-6.1-terra`) + Claude Code가 결과 분석·지시문 수정 | 구독 안 |
| 첫 구축 전체 추출 | OpenAI **배치 API**(`gpt-6.1-terra`, 가격 50%, 24시간 안 처리) | DART 1,063개 **$12.6** (긴 회사 97개는 구독 Codex로) · 뉴스 2,471건 **$14.4**(v5) |
| 매일 밤 새 뉴스 | OpenAI API 일반 요청(`gpt-6.1-terra`). 아침 전에 결과를 바로 받아야 해서 배치는 쓰지 않는다 | 요청(묶음)당 약 $0.012. 첫 실전(시험 종목 18개)은 하룻밤 묶음 86개, 약 $1 |

배치는 대기열 한도(300만 토큰)에 맞춰 나눠 내고, 자동 반복 스크립트가 10분마다 결과를 받고 다음 배치를 낸다.

- **그래프 구성**: 공시·뉴스 최종본과 제품 사전을 보고 노드·관계 스키마를 확정해 만든다. 그래프는 지금까지 쌓인 뉴스로 처음 만들고, 이후에는 매일 밤 새 뉴스의 추출을 쌓아 두었다가 일정 주기로 한 번씩 반영한다(매일 아님, 주기 미정).
