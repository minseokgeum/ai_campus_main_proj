# 당신이 잠든 사이에: 아침 브리핑 앱 (Streamlit)

모델이 만든 아침 카드, 야간선물 1분봉, 뉴스 묶음을 그대로 읽어 증권사 앱 안의 아침 브리핑을 재현한다.
고객이 보는 화면은 11/11부터 `src/front`(http://127.0.0.1:8520)에서 따로 만든다. 이 앱은 검증·연구용 화면이다.
앱은 계산을 하지 않는다. 계산은 `pipeline/`이 하고, 앱은 그 결과 파일만 읽는다.
그래서 실시간 경로가 같은 형식의 파일을 남기면 화면이 그대로 바뀐다.

## 열기

```bash
cd ~/4Digit/src/app && ~/4Digit/.venv/bin/streamlit run app.py   # http://127.0.0.1:8510
```

같은 폴더의 `앱_열기.command`를 두 번 클릭해도 된다. 이 컴퓨터에서만 열린다(127.0.0.1).

## 화면

| 화면 | 내용 | 자료 |
|---|---|---|
| 아침 브리핑 | 휴대폰 폭. 위에서부터 아래 순서로 보여 준다. | 아침 카드·계좌 후보·뉴스·일정(연구 폴더 fomc_dates·fred_release_dates, 만기일은 매월 둘째 목요일 규칙) |
| 밤사이 흐름 | 야간선물 가격·거래량·15분 보도량. 주제별 최초 보도 표식과 공시 접수선을 함께 그린다. | 1분봉·뉴스 |
| 새 소식 | 주제별 정보를 모은다. 정렬은 내 계좌 연결 여부로 한다. | 뉴스 |
| 예측 vs 실제 | 과거 재생 1년치를 누적한다. 검증 기간을 따로 보여 준다. | track_*.csv, forward_log.csv |
| 모델 한눈에 | 회귀식 세 개와 검증 기간 결과를 보여 준다. 결과는 track 파일에서 바로 계산한다. | track |
| 데이터 연결 | 화면 숫자마다 지금 읽는 곳과 운영 경로를 정리한다. | — |

**아침 브리핑의 순서**
1. 하루 주의 문구(월요일)
2. 계좌 예상 변화(원)와 계좌 범위(연구 중)
3. 금액 기준 믿을 정도
4. 밤사이 한눈에
5. 연결된 새 소식 3개
6. 다가오는 일정 7일(미국 FOMC·CPI·고용지표, 국내 옵션·선물 만기일)
7. 종목별 노란띠·08:11 등급·종목 주의 문구
8. 수량 바꿔 보기
9. 시각 탭 07:30 → 08:11 → **09:00 개장 후**: 오늘 결과(예상 vs 실제 금액, 범위 안 종목 수, 장전 방향 일치), 종목별 07:30→08:11→09:00 흐름, 그날까지 최근 20거래일 누적 기록

**새 소식에 모으는 정보**
- 최초·후속 보도
- 연결 근거(관계표 근거 링크)
- 핵심 숫자(원문 인용)
- 같은 시간대 시장 반응
- 장 전 확인할 것
- AI 문장(검사 통과분)

## 자료 만들기 (과거 재생)

```bash
cd ~/4Digit/research/overnight_backtest
.venv/bin/python ~/4Digit/src/app/pipeline/build_model_data.py     # 약 2~4분(패널 읽기)
~/4Digit/.venv/bin/python ~/4Digit/src/app/pipeline/build_night_news.py
```

- `build_model_data.py`가 하는 일:
  - 패널 기간(2025-10-21~2026-10-26)의 모든 거래일에 대해 `workbench/morning_card.build_card`를 그대로 호출한다. 봉인 통과 규칙만 쓴다.
  - 예시 계좌 5개의 계좌 범위 후보 AS1(E63)을 그날 이전 오차로만 계산한다.
  - 개장 뒤 결과는 따로 붙인다.
- 화면 예시 날짜는 다음과 같다.
  - 6/25: 마이크론 실적 밤. 뉴스가 연결된 날이다.
  - 가장 크게 내린 밤
  - 보유 종목에 실적 공시 주의가 있는 월요일
  - 패널 마지막 날
- `build_night_news.py`가 하는 일:
  - 야간선물은 KIS 과거 1분봉에서 그날 밤만 잘라 쓴다. 봉 시각은 시작 시각 기준이다.
  - 뉴스는 단독 검증판(4Digit-solo)의 재생 실행 결과를 옮겨 온다.
  - 6/25 이외의 날은 뉴스가 '연결 전'으로 나온다.

시장 API·실시간 수집·예약은 실행하지 않는다. 연구 data/와 기존 결과는 바꾸지 않는다.

## 운영 연결 (같은 파일 형식으로 교체)

1. `live_refresh.py`가 끝난 장 자료를 받는다.
2. 07:30에는 `morning_card.py --root <폴더> --slot 0730`, 08:11에는 `--slot 0811`을 돌린다. 결과는 `data/model/days/<T>.json`과 같은 칸으로 저장한다.
3. 팀 RSS 수집기(`rss_news/src/rss_pipeline.py` → `combined_rss.sqlite3`)의 결과를 주제 묶음(최초·후속 시각), 관계 DB 연결, 문장 검사 순서로 거쳐 `data/news/<T>.json`에 저장한다.
4. 야간장 1분봉은 `data/night/<T>.csv`에 저장한다.
5. 개장 뒤 대조 결과는 `track_*.csv`에 누적한다.

## 한계

- **과거 재생:** 모든 수치는 과거 자료 재생이다. 장 전 실제 수신·발행 기록이 아니다. I16 실제 수신은 0건이다.
- **계좌 범위:** 계좌 범위 AS1은 봉인 미달 후보다. 무작위 계좌 검증에서 조용한 밤 포함률이 72.2%로 75%보다 낮았다. 그래서 화면에는 '연구 중'으로 표시한다.
- **수량 변경:** 수량을 바꾸면 계좌 범위를 숨긴다. 구성이 바뀌면 다시 계산해야 하기 때문이다.
- **뉴스 범위:**
  - 뉴스는 6/25 하루만 연결돼 있다.
  - 사건 묶음 자동화와 관계 DB는 팀 쪽에서 아직 구현하지 않았다.
  - AI 문장이 없는 주제는 원문 영어 제목이 그대로 나온다.
- **실제 기록:** '예측 vs 실제' 아래의 실제 매일 기록(forward_log)은 이전 규칙(E19)이다. 위의 과거 재생과 섞지 않는다.
- **보안 점검:** 보안 동적 점검(DAST)은 실행하지 않았다.
